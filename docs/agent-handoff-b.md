# Codex 交接：项目全貌与已完成的工作

`cf-comments` 源于个人博客从 Waline 迁移的需求，但定位是可独立部署的评论系统。一个 Cloudflare Worker 和一个 D1 数据库提供评论 API、嵌入组件和同源审核台。宿主只需接入组件，仍可使用自己的托管、主题与路由。这份交接记录我对项目的理解及参与完成的工作，不规定继任者的职责。

## 一条评论如何流转

组件用规范化的站内路径标识讨论串。访客可匿名发表评论，选择 GFM 或 MFM；Worker 重新解析并清理正文，再存入 D1，按站点配置先审后发或先发后审。公开列表按游标分页，待审子树不公开；隐藏或删除的父评论有可见后代时保留占位，避免回复失去上下文。站长通过审核台处理评论；邮件用 D1 outbox 与 Cron 重试，回复通知须先验证邮箱。系统不承担账号、阅读量或联邦社交功能。

我把读者组件、审核台及其资源接入同一 Worker 构建，并用模拟接口和预发布数据验证浏览、预览、楼中楼和审核流程。实时预览复用 Worker 的 GFM/MFM 渲染管线，仅在首次开启时加载 `preview.js`，不调用 `/v1/preview`；正式发布仍由服务端独立清理。我也完成了 Material 3 布局、键盘与减少动效适配、Gravatar 首字回退和 Misskey 表情解析。启用 Gravatar 后公开链接含可比对的邮箱哈希，不含明文邮箱，但也不是匿名标识。相关提交：`fe33ec0`、`8a2efdb`、`3b04753`、`d19f8f7`、`071abca`。

## 线上切换与持续维护

我把 Astro/Fuwari 博客的文章、关于、友链入口从 Waline 切到新服务，保留尾斜杠路径，处理 Swup 换页时的挂载与清理，并让配色随博客主题变化。切换前验收了历史回复树、跨域请求、导航和审核；测试留言已清理，未改动历史记录。迁移与最终对账由 AGY 完成：跳过首页 3 条测试，迁入 18 条，最终无须补迁；后续只为 12 条符合条件的历史评论补头像哈希，未恢复邮箱或开启订阅。这些是迁移时的数字，不是当前线上计数。父仓库相关提交：`598f15b`、`b572417`、`bd6838c`、`936c695`。

我建立了公开 GitHub 仓库的检查与自动发布流程，AGY 配置并验证了首次生产发布。PR 只检查；开启 `CF_DEPLOY_ENABLED` 后，推送 `main` 会在检查通过后核对现有 Worker、域名和 D1 绑定，再部署代码与资源，不会执行数据库迁移。业务密钥留在 Cloudflare。普通组件更新不用重发博客，但主题或挂载改动需要另发 Pages。我也整理了仓库结构、双语 README，以及部署和迁移文档。相关提交：`9386142`、`687f0b2`。
